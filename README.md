## サービス概要

**Herb Recipe Lab** は、ハーブティーのブレンドレシピを記録・整理・共有できるアプリです。

「美味しかった配合を忘れてしまう」「苦手だったブレンドをまた作ってしまう」——そんなハーブブレンドの試行錯誤を、**「配合（STEP 1）」→「飲用後の感想（STEP 2）」の2段階で記録**することで、"あの一杯" を再現可能なレシピとして蓄積できます。味の好みや手持ちのハーブからレシピを検索でき、自分だけのハーブデータベースを育てられるのが特徴です。

### 技術選定の理由

- **Ruby on Rails**: 規約による高い開発速度と、個人開発の生産性を重視して採用。
- **Rails 7.2**: 学習・開発の段階で Rails 7 系の知見が十分にあり、参考にできる記事や事例も多いため、最新の Rails 8 ではなく実績のある 7.2 を選択。新機能の検証より、限られた開発期間で確実に機能を完成させることを優先した。
- **Hotwire（Turbo / Stimulus）**: ページ全体を再読み込みせず、変更があった部分だけをサーバー側のHTMLで差し替えることで、JavaScript を最小限に抑えつつ軽快な操作感を実現するため採用。ブックマークの非同期更新（Turbo Stream）や、検索欄の開閉・タグ入力などのリッチなフォーム操作（Stimulus）で活用。
- **PostgreSQL + GoodJob**: メール送信などの時間のかかる処理を将来的にバックグラウンド化するための基盤として、ジョブ管理に GoodJob を採用。ジョブの状態を PostgreSQL に保存するため、別途 Redis のようなミドルウェアを用意せずに済み、構成をシンプルに保てる。
- **Cloudinary**: Render の永続ストレージ制約を回避し、画像配信を外部化。
- **Neon**: 本番DBにサーバーレスの PostgreSQL（Neon）を採用し、DB の運用・スケーリングをマネージドに任せている。

## 工夫した点・技術的チャレンジ

- **2段階保存フローの設計**: 「配合（`recipes`）」と「飲用後の感想（`drinking_logs`）」を別アクション・別テーブルで保存。淹れる前と後で記録タイミングが異なる、という実体験に即したデータモデルを設計した。
- **単位統一・換算ロジック**: `recipe_herbs.unit`（小さじ / 大さじ / g / 枚 / 個）を enum で管理し、200ml基準で分量を統一的に扱えるようにした。
- **検索ロジックの集約**: Ransack に加え、使用ハーブ AND・風味・効能・禁忌除外のクロス検索を `ApplicationController#apply_herb_based_filters` に集約。コントローラを薄く保ちつつ、レシピ・市販レビュー双方で再利用している。
- **N+1 対策の徹底**: 一覧取得では `includes(:user, :drinking_log, recipe_herbs: :herb)` を用い、関連先のクエリ発行を抑制。
- **Hotwire によるUX改善**: ブックマークの追加 / 解除を Turbo Stream でページ遷移なしに反映。検索欄の絞り込みパネル開閉、配合行の動的追加、タグ入力、画像プレビューなどを Stimulus コントローラで実装し、入力中のコンテキストを保ったまま操作できるようにした。
- **Cloudinary + ActiveStorage による画像保存** とバリアント生成。
- **ログイン不要の閲覧導線**: 公開レシピ・ハーブ図鑑・市販レビューは未ログインで閲覧可能にし、投稿・保存などの操作時にのみログインへ誘導することで、新規ユーザーの離脱を抑える設計にした。

## 開発環境セットアップ

本プロジェクトは Docker 上で動作します。

```bash
# 1. リポジトリをクローン
git clone https://github.com/Elu-72b/Herb_Recipe_Lab.git
cd Herb_Recipe_Lab

# 2. 環境変数ファイルを用意（.env.example をコピーして値を設定）
cp .env.example .env

# 3. コンテナをビルド
docker compose build

# 4. データベースを作成・マイグレーション・初期データ投入
docker compose run --rm web bin/rails db:create db:migrate db:seed

# 5. コンテナを起動
docker compose up
```

> `.env` には Cloudinary（画像保存）やメール送信に必要なキーを設定します。各キーの一覧は `.env.example` を参照してください。

起動後、ブラウザで http://localhost:3000 にアクセスします。

```bash
# よく使うコマンド（すべて docker compose exec web 経由）
docker compose exec web bin/rails test              # テスト実行（Minitest）
docker compose exec web bin/rails db:migrate        # マイグレーション
docker compose exec web bin/rails tailwindcss:build # CSS ビルド
docker compose exec web bin/rails console           # コンソール
```

開発環境では gem `letter_opener_web` により `/letter_opener` で送信メールをブラウザ確認できます。

## 1. サービス概要

このサービスは、ハーブティーのブレンドレシピを記録・整理・共有できるアプリです。
ハーブの配合、味のメモ、期待する効果などをまとめて管理できます。
ハーブブレンドを楽しむ人が、自分のレシピを再現可能な形で記録し、経験を蓄積できることを目的としたサービスです。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

ハーブブレンドを自作する中で、
「美味しかった配合を忘れる」「苦手だったブレンドを再度作ってしまう」
という失敗を繰り返していました。
スマートフォンのメモやノートでは、
ハーブの割合・味の印象・体調の変化などを体系的に整理できず、
「あの一杯」を再現できないもどかしさを感じたことが出発点です。
また、自分の好みに合うレシピを探そうとしても、
既存のネット検索では理想のブレンドに辿り着けないという課題にも直面しました。

### 2-2. なぜそれが「気になった」のか

ハーブティーは、味の好みや気分に合わせて微調整する楽しさがある一方で、
その試行錯誤が「データ」として蓄積されない限り、個人の経験を次に活かすことができません。
現状、ブログやInstagramなどでは魅力的なブレンドが数多く発信されていますが、
情報が埋もれてしまいやすく、自分に合ったレシピを検索・再現することが極めて困難です。

また、ブレンド初心者にとっては、どの単品ハーブを揃えれば良いかの判断が難しく、
購入のハードルが高いという現状もあります。
ハーブブレンドは本来、経験の積み重ねが重要であるにも関わらず、有益な知見が埋もれてしまい、
初心者が一歩踏み出しにくい環境にあることに強い違和感を抱きました。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

記録の散乱： 配合、味、感想を体系的に整理・記録するのが困難。

検索の困難さ： 自分の嗜好や手持ちのハーブに合致するレシピが見つからない。

### 3-2. 本当に解決したい課題

- 「ハーブブレンドの試行錯誤を、再現可能な形で資産化できない」という問題の解消。

- 直感的な記録と振り返りを通じ、自分の「好き」という感覚を確かなレシピ（資産）として確立できる体験の提供

- 個人のブレンドレシピと風味記録をデータ化し、経験や知識を他者と共有・活用できるプラットフォームの実現。

## 4. 想定ユーザーについて

### 4-1 想定しているユーザー

①自宅に数種類のハーブをストックし、ブレンドを施行している人

②ハーブティーのブレンドに挑戦したい初心者

生活・状況設定：

### 4-3 実際に使われる可能性について

  ハーブブレンドの

  などを1つの場所で整理できるため。

### 5-2 それでも自分が作りたい理由

既存のレシピサービスは主に料理レシピを対象としており、

- ハーブブレンドの配合
- 味の印象
- 体調への効果

  などを体系的に整理することには向いていないと感じました。

### 5-3 差別化

本アプリは、単なるレシピ記録を超え、**「個人の嗜好に徹底的に寄り添う」**体験を提供します。

ポジティブな味ベース検索：
効能だけでなく「甘み」「スパイシー」「フローラル」といった味の好みからレシピに辿り着ける設計。

ブレンド検索時の除外フィルタリング：
苦手なハーブや禁忌（カフェイン、特定成分）をあらかじめ設定することで、ブレンドを検索時に「このブレンドは苦手なハーブが入ってるから飲めないな」と諦めることがなくなります。

嗜好の資産化：
「この配合は好き」「これはミントが強すぎた」という試行錯誤を蓄積し、自分だけの「至高の一杯」を実現させ、またそれを再現可能にします。

「購買」ではなく「研究（記録）」への特化:
既存のサイトの多くは「売るためのレシピ」や「完成された商品」が主役です。対して「Herb Recipe Lab」は、「手元の素材でどう美味しくするか」という試行錯誤の過程そのものを記録することができます。

## 7. このアプリで実現すること

### MVPで作る機能

- ユーザー認証機能

  メールアドレスによる新規登録、ログイン、ログアウト機能。

- ハーブ管理機能（マスタ・自由入力）

  50音順に整理されたハーブマスタから選択。

- マスタにない材料は「その他」として自由記述で追加可能。

- 二段階保存によるブレンド研究記録

  STEP 1（淹れる前）: 日付、タイトル、ハーブ配合、200mlあたりの分量（g/小さじ単位統一切り替え）を記録。
  STEP 2（飲用後）: 実際の味や香りの感想を、レシピを振り返りながら追記。

- レシピ共有機能

  投稿されたレシピの一覧表示、詳細表示。

### 本リリースで作る機能

- 5段階評価 ＆ 8要素の風味チャート
  「甘味・苦味・渋味・清涼感・スパイシー・清涼感・フルーティー・酸味・華やかさ」の8つの指標で味を客観的に可視化。
  自己分析や「好みの近いユーザー」とのマッチングの基礎データとなります。

- ハー図鑑（Turbo Stream実装）

  レシピ入力画面を離れることなく、非同期でハーブの画像・風味・効能・禁忌を確認できる機能。
  50音順、風味ジャンル、効能ジャンルでの並び替え・絞り込みに対応。

- 多角的なレシピ検索機能

  使用ハーブ、期待する効果、好みの風味タグを組み合わせたクロス検索。

- コミュニティ・ストック機能

  ユーザー間のフォロー機能、ブックマーク、他ユーザーのブレンドレシピの評価機能。

- 外部API（Gemini API）連携によるブレンド提案

  手持ちのハーブから、相性の良い組み合わせや期待できる効果をAIがアドバイス。

- 市販ハーブティー・飲用ログ機能

  自作レシピだけでなく、既製品の飲用感も同様のチャートで記録可能に。

## 8. このアプリの懸念点とその対策

### 懸念点

- 何が問題になりそうか：ハーブブレンドをするユーザー数が限定的である可能性。

- なぜそう思うか：ハーブブレンドは一般的な料理や飲み物と比べ、趣味人口が比較的少ない分野であるため。

- 対策：ハーブブレンドだけでなく、市販ハーブティーの飲用記録を投稿できるようにすることでハーブティー初心者でも飲んでみたいと思ってもらえるようにする。
